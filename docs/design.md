# จดจ่าย — design v1 (design tokens · mobile-native rules · หน้าจอ)

ไฟล์นี้คือสัญญาด้านหน้าตา/UX ของ v1 · คู่กับ `docs/schema.sql` (ข้อมูล) และ `docs/PLAN.md` (แผนรวม)
stack ล็อกแล้ว (Next.js 15 App Router + TS, Tailwind v4, Better Auth, Drizzle + Neon, PWA บน Vercel)

หลักการ 3 ข้อ (ใช้ตัดสินตอนเถียงกัน)
1. **บันทึกเร็วที่สุด** — เปิดมาแล้วจบในไม่กี่วินาที ถ้า flow ยาวขึ้น ต้องมีเหตุผลด้านข้อมูลรองรับ
2. **ตัวเลขต้องเชื่อถือได้** — ยอดที่แสดงคือยอดที่ถูกจริง ไม่มี "ประมาณ" ไม่มีตัวเลขกระพริบเปลี่ยนทีหลังโดยไม่มีสาเหตุ
3. **รู้สึกเหมือนแอปมือถือ** ไม่ใช่เว็บที่ย่อลงมา — ไม่มี reload, ไม่มี modal กลางจอ, ปุ่มอยู่ในระยะนิ้วโป้ง

เป้าอุปกรณ์: กว้าง 390×844 (iPhone 14/15) เป็นหลัก · กว้างสุด 430 · แคบสุดที่รับ 320 (จอเล็กต้องไม่แตก)
ธีม: ตามระบบเป็นค่าเริ่มต้น + สลับเองได้ (สว่าง/มืด/ตามระบบ) ในหน้าตั้งค่า

## 1. Design tokens

### 1.1 สี

ค่าคอนทราสต์ในวงเล็บวัดจริงแล้ว (เทียบกับพื้นของธีมนั้น) — ข้อความ ≥ 4.5:1, ขอบช่องกรอก ≥ 3:1

| token | light | dark | ใช้ที่ |
|---|---|---|---|
| `--bg` | `#EAEFF4` | `#0B1220` | พื้นหลังหน้า (การ์ดขาวบนพื้นนี้ = **1.16:1** — วัดแล้ว การ์ดไม่กลืนพื้น) |
| `--surface` | `#FFFFFF` | `#121B2C` | การ์ด, แถบแท็บ, bottom sheet |
| `--surface-2` | `#F1F3F6` | `#18233A` | พื้นรอง: ชิปทีเลือก, ช่องกรอกที่โฟกัส |
| `--border` | `#E3E7ED` | `#24314D` | เส้นคั่น (decorative — ไม่ต้องผ่าน 3:1) |
| `--border-strong` | `#7E8794` (3.1:1 บนพื้น · 3.6:1 บนการ์ดขาว) | `#5B6880` (3.1:1) | ขอบช่องกรอก/ปุ่ม outline ที่ต้องมองเห็น |
| `--text` | `#101828` (17.8:1) | `#E6EBF2` (14.4:1) | ข้อความหลัก |
| `--text-muted` | `#616B7A` (4.7:1 บนพื้น · 5.4:1 บนการ์ดขาว) | `#93A0B5` (6.5:1) | ข้อความรอง, เวลา, label |
| `--income` | `#157A3B` (4.7:1 บนพื้น · 5.4:1 บนการ์ดขาว) | `#4ADE80` (9.9:1) | รายรับ (ข้อความ + ไอคอน) |
| `--expense` | `#BE123C` (5.9:1) | `#FB7185` (6.4:1) | รายจ่าย |
| `--balance` | `#0E7490` (5.0:1) | `#22D3EE` (9.5:1) | คงเหลือ, โอน |
| `--warn` | `#A64E07` (4.9:1 บนพื้น · 5.7:1 บนการ์ดขาว) | `#FBBF24` (10.3:1) | ใกล้เกินงบ (ใช้ไป ≥ 80%), เตือนข้อมูลหาย |
| `--focus` | `#2563EB` | `#60A5FA` | วงแหวนโฟกัส (`focus-visible`) |
| `--on-accent` | `#FFFFFF` | `#08101F` | ข้อความบนปุ่มทึบสี accent |

สีสำหรับ "พื้นทึบ" (chart, badge, ปุ่ม) ใช้เฉดสว่างกว่าได้ เพราะไม่ใช่ข้อความ:
`#16A34A` (เขียว) · `#E11D48` (แดง) · `#0891B2` (ฟ้า) · `#D97706` (เหลือง)

ชุดสีกราฟ 8 สี ใช้เรียงตามนี้ (ทุกสีผ่าน 3:1 ทั้งบนพื้นสว่างและมืด — วัดแล้ว):
`#0891B2` `#7C3AED` `#D97706` `#16A34A` `#DB2777` `#0D9488` `#65A30D` `#E11D48`
กติกา: กราฟรายจ่ายห้ามใช้เฉดเขียว (เขียว = รายรับในแอปนี้) · ถ้าหมวดเกิน 8 ให้รวมที่เหลือเป็น "อื่น ๆ" ไม่วนสีซ้ำ

กติกาสีที่ห้ามละเมิด
- **ห้ามใช้สีอย่างเดียวสื่อความหมาย** — ทุกรายการมีเครื่องหมาย `+`/`−` หรือคำกำกับ เพื่อคนตาบอดสี
- แดง/เขียวใช้เฉพาะ "ทิศทางเงิน" เท่านั้น ห้ามใช้เป็นสีตกแต่งปุ่มหรือสถานะ error ทั่วไป (error ใช้ `--warn` + ไอคอน + ข้อความ)
- โหมดมืดห้ามใช้เงาเป็นตัวแยกชั้น (มองไม่เห็น) — แยกด้วย `--surface` ที่ต่างกัน 2 ระดับ + `--border`
- **การ์ดต้องไม่กลืนพื้น** (วัดเป็นอัตราส่วนการ์ด:พื้น): โหมดสว่าง `--surface #FFFFFF` บน `--bg #EAEFF4` = **1.16:1** · โหมดมืด `#121B2C` บน `#0B1220` = 1.09:1 แต่ได้เส้น `--border` (#24314D เทียบการ์ด 1.33:1) ช่วยแยกชั้น
  เดิม `--bg #F6F7F9` ให้แค่ **1.07:1** = การ์ดจมหายบนจอจริง (เจอตอนเรนเดอร์ theme-preview.html) — ถ้าจะทำให้พื้นสว่างกว่านี้ต้องชดเชยด้วยเส้น/เงาที่เห็นได้ ห้ามปล่อยให้ต่ำกว่า 1.15:1
  หมายเหตุ: พอพื้นเข้มขึ้น 3 token ที่อ่าน "บนพื้น" ต้องเข้มตามด้วย (`--text-muted`, `--income`, `--warn`) — ตัวเลขใหม่ในตาราง 1.1 วัดบนพื้นใหม่แล้ว ถ้าแก้ `--bg` อีกต้องวัดซ้ำทั้งชุด
  **ตัวที่ margin น้อยสุดคือ `--balance` บนพื้นสว่าง = 4.63:1 (เหลือ 0.13)** — ใครจะขยับ `--bg`/`--surface` ต้องรัน `contrast_check.py` ก่อน (สคริปต์เตือนเองเมื่อ margin < 0.3) ไม่ต้องรอให้ตาหรือคนอื่นจับได้

### 1.2 ฟอนต์

| บทบาท | ค่า | หมายเหตุ |
|---|---|---|
| ฟอนต์หลัก | **IBM Plex Sans Thai** | มีบน Google Fonts จริง (ตรวจแล้ว: weight 100–700) — โหลดผ่าน `next/font/google` subset `['thai','latin']` น้ำหนัก **400 / 600 / 700** เท่านั้น (ไม่โหลด 5 น้ำหนัก) `display: "swap"` |
| ฟอนต์สำรอง | `system-ui, "Sarabun", sans-serif` | ก่อนฟอนต์โหลดเสร็จต้องอ่านออก ไม่ใช่ tofu |
| ทางเลือกอนาคต | LINE Seed Sans TH | สัญญาอนุญาต SIL OFL 1.1 ใช้เชิงพาณิชย์ได้ (LY Corp. แนะนำให้ใส่เครดิต) แต่ต้อง self-host เอง → ยังไม่ทำใน v1 |

ทำไม IBM Plex Sans Thai ไม่ใช่ LINE Seed: v1 ได้ 0 build step กับ 0 ไฟล์ font ในเรป (Google โฮสต์ + next/font ทำ subset ให้อัตโนมัติ) การย้ายไป LINE Seed ทำทีหลังได้โดยแก้ที่ `--font-sans` ที่เดียว

สเกลตัวอักษร (หน่วย px / line-height)

| ชื่อ | ขนาด/บรรทัด | ใช้ที่ |
|---|---|---|
| display | 32 / 40 | ยอดเงินใหญ่หน้าแรก (น้ำหนัก 700) |
| h1 | 24 / 32 | ชื่อหน้า |
| h2 | 20 / 28 | หัวข้อ section, ชื่อหมวด |
| body | 15 / 24 | เนื้อความ, รายการทั่วไป (ต่ำสุด 15 — ไทยมีสระบน/ล่าง อ่านยากถ้าเล็กกว่านี้) |
| caption | 13 / 18 | เวลา, ป้ายกำกับ, ข้อความช่วย |

- บรรทัดไทยใช้ line-height ≥ 1.5 เท่าตัวอักษรเสมอ (สระ/วรรณยุกต์ซ้อนกัน)
- ห้ามใช้ font-weight ต่ำกว่า 400 บนพื้นมืด — ตัวไทยจะบางจนอ่านไม่ออก
- **ตัวเลขเงิน**: ทุกที่ที่แสดงจำนวนเงินใส่ `font-variant-numeric: tabular-nums` และจัดชิดขวา
  ยังไม่ยืนยันว่า subset ไทยของ Plex รองรับ `tnum` (ตรวจจากไฟล์ woff2 ตรง ๆ ไม่ได้เพราะบีบอัด) — ถ้าตัวเลขยังขยับความกว้างตอนติ๊ก ให้สลับเฉพาะตัวเลขในคีย์แพด/ช่องกรอกเป็น `ui-monospace, "IBM Plex Mono", monospace` (knob นี้ต้องเช็คบนเครื่องจริงตอนทำเฟส 2)
- **การแสดงจำนวนเงิน**: เก็บเป็นสตางค์ (bigint) → แสดงผลแปลงที่ชั้นแสดงผลเท่านั้น ผ่าน helper เดียว `formatSatang(satang: number, opts?)` ใช้ `Intl.NumberFormat('th-TH', { style: 'currency', currency: 'THB' })` · ห้ามหาร 100 กระจัดกระจายในโค้ด

### 1.3 Spacing / layout

ใช้สเกล default ของ Tailwind (ฐาน 4px) — ไม่สร้างสเกลใหม่ · กติกาใช้งาน:

- padding ขอบหน้า: 16 · padding ในการ์ด: 16 · ระยะห่างแนวนอนระหว่าง element: 8
- ระยะระหว่าง section: 24 · ระยะก่อน bottom tab bar: 16 + safe area
- ความสูงแถวในลิสต์: 56 (ขั้นต่ำ 44) · ไอคอนในแถว: 20
- ความกว้างสูงสุดของเนื้อหาเมื่อเปิดบนจอใหญ่: 430px กลางจอ (ไม่ยืดเต็มจอ — ไม่อยากอ่านบรรทัดยาว)

### 1.4 Radius

`8` ช่องกรอก/ปุ่มเล็ก · `12` ปุ่มหลัก/ชิป · `16` การ์ด · `20` bottom sheet (มุมบนเท่านั้น) · `999` แถบความคืบหน้า (progress), avatar

### 1.5 Shadow

| token | ค่า | ใช้ที่ |
|---|---|---|
| `--shadow-card` | `0 1px 2px rgb(2 6 23 / .06)` | การ์ด (โหมดสว่างเท่านั้น) |
| `--shadow-sheet` | `0 -8px 32px rgb(2 6 23 / .18)` | bottom sheet (ยิงขึ้นบน) |
| `--shadow-sticky` | `0 4px 12px rgb(2 6 23 / .06)` | แถบแท็บ/FAB ตอนเลื่อน |

การ์ดบนโหมดสว่าง: `--shadow-card` + เส้น `--border` 1px · พื้น `--bg` เข้มพออยู่แล้ว (1.16:1) เงาจึงเป็นแค่ความเนียน ไม่ได้ทำหน้าที่แยกชั้น
โหมดมืด: ตั้ง `--shadow-card: none` แล้วแยกชั้นด้วย `--border` (`#24314D` เทียบการ์ด 1.33:1) + `--surface` — เงาบนพื้นดำมองไม่เห็น ใช้ไปก็เสียเปล่า

### 1.6 Motion + z-index

- แตะ/กด: 120ms `ease-out` (scale 0.98) · bottom sheet เข้า/ออก: 240ms `cubic-bezier(.32,.72,0,1)` · แจ้งเตือน: 200ms fade+slide 8px
- ห้าม animate ความกว้าง/ความสูง (กระตุกบนมือถือ) — ใช้ transform/opacity เท่านั้น
- `@media (prefers-reduced-motion: reduce)` → 0ms ทุกอย่าง (ยกเลิกการสไลด์ ไม่ใช่แค่เร็วขึ้น)
- z-index: เนื้อหา 0 · แถบแท็บ 20 · FAB 30 · bottom sheet + backdrop 40 · toast 50 · (ไม่ใช้ค่าอื่นนอกจากนี้)

### 1.7 ประกาศใน Tailwind v4

Tailwind v4 ใช้ CSS-first config — ต้องใช้ `@theme inline` เมื่อค่าอ้างตัวแปรอื่น
(ยืนยันจากเอกสาร Tailwind v4 หัวข้อ "Referencing other variables"):

```css
/* src/app/globals.css */
@import "tailwindcss";
/* ถ้าสลับธีมด้วยคลาส .dark ไม่ใช่ prefers-color-scheme (เวอร์ชัน v4 ที่ลง ตรวจ syntax นี้อีกครั้ง) */
@custom-variant dark (&:where(.dark, .dark *));

@theme inline {
  --color-bg: var(--bg);
  --color-surface: var(--surface);
  --color-surface-2: var(--surface-2);
  --color-border: var(--border);
  --color-border-strong: var(--border-strong);
  --color-text: var(--text);
  --color-text-muted: var(--text-muted);
  --color-income: var(--income);
  --color-expense: var(--expense);
  --color-balance: var(--balance);
  --color-warn: var(--warn);
  --font-sans: var(--font-thai);
  --radius-card: 16px;
}

:root {
  --bg: #EAEFF4; --surface: #FFFFFF; --surface-2: #F1F3F6;
  --border: #E3E7ED; --border-strong: #7E8794;
  --text: #101828; --text-muted: #616B7A;
  --income: #157A3B; --expense: #BE123C; --balance: #0E7490; --warn: #A64E07;
  --focus: #2563EB;
}
.dark { /* ค่าโหมดมืดตามตาราง 1.1 */ }
```

ผลลัพธ์ที่ต้องการ: ใช้ `bg-surface` `text-muted` `text-expense` ได้ตรง ๆ และสลับธีมได้โดยเปลี่ยนคลาสที่ `<html>` โดยไม่ต้องแก้ component

## 2. Mobile-native rules (checklist — ทุกข้อมีค่าที่วัดได้)

**จอ/ระยะปลอดภัย**
- `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">` — จำเป็นสำหรับ `env()`
- ระยะปลอดภัย: `padding-top: env(safe-area-inset-top)` ที่หัวหน้า · `padding-bottom: calc(env(safe-area-inset-bottom) + 56px)` ที่เนื้อหา (กันแถบแท็บทับ) · แถบแท็บสูง `56px + env(safe-area-inset-bottom)`
- ความสูงเต็มจอใช้ `100dvh` ไม่ใช่ `100vh` (ไม่ให้แถบ URL ของ Safari กินพื้นที่แล้วล้น)
- `overscroll-behavior: none` ที่ `body` (ปิด pull-to-refresh ที่ทำให้ข้อมูลเบิ้ล) และ `overflow-x: hidden`
- หน้าเว็บไม่มี scroll แนวนอนทุกขนาด · ทดสอบที่ 320 / 390 / 430px

**การแตะ**
- tap target ขั้นต่ำ **44×44px** ทุกตัว (ปุ่ม, แถว, ไอคอนในหัวหน้า) · แถวในลิสต์สูง 56 → ทั้งแถวเป็นพื้นที่แตะได้ (ใช้ `<button>`/`<a>` ครอบแถว ไม่ใช่ `div` + onClick)
- `-webkit-tap-highlight-color: transparent` + `touch-action: manipulation` (ตัดดีเลย์ 300ms และแถบไฮไลต์เทาของ iOS)
- ปุ่มหลักของ flow (บันทึก) อยู่ในระยะนิ้วโป้ง: วางไว้ **ล่างขวา** ของ bottom sheet สูง 56 ระยะจากขอบล่าง ≥ 16 + safe area — ไม่ไว้หัวจอ
- FAB (ปุ่ม +) อยู่เหนือแถบแท็บด้านขวา ห่างจากขอบขวา 16 · ห่างจากแถบแท็บ 16 (อยู่ในโซนนิ้วโป้ง)

**การกรอกจำนวนเงิน**
- ช่องจำนวนเงินเป็น `<input>` จริงเสมอ ตั้ง `inputmode="decimal"` `autocomplete="off"` `enterkeyhint="done"` (ผู้ใช้ screen reader/คีย์บอร์ดระบบใช้ได้) — คีย์แพดของแอปเป็น layer เสริม ไม่ใช่ทางเดียว
- คีย์แพดตัวเลขของแอปเอง (0-9, จุดทศนิยม, ลบทีละตัว, กดค้าง = ล้าง) เปิดอัตโนมัติเมื่อ bottom sheet ขึ้น — ไม่รอคีย์บอร์ดระบบ
- ขนาดปุ่มคีย์แพด ≥ 56px สูง · ปุ่มลัดยอดที่เคยใช้บ่อย (20/50/100/500) อยู่แถวบนสุดของคีย์แพด
- ปุ่ม **บันทึก** ปิดการใช้งาน (disabled) เมื่อจำนวนเป็น 0/ว่าง และปุ่มสูง 56px เสมอ (ไม่ให้ความสูงเปลี่ยนตอน enable)

**Bottom sheet แทน modal กลางจอ**
- bottom sheet: มุมบน 20px, มี drag handle, ปัดลง = ปิด, backdrop คลิก = ปิด, เปิดแล้ว focus ไปที่ช่องจำนวนเงิน
- ใช้ `<dialog>` + `showModal()` ของเบราว์เซอร์ (ได้ focus trap + ปุ่ม Esc ฟรี) แล้วจัดสไตล์เป็น sheet — ไม่ดึงไลบรารี dialog
- ปิด sheet ต้องไม่ reload หน้า และถ้ากรอกค้างอยู่ ให้ถามก่อนทิ้ง (เฉพาะกรณีมีข้อมูลที่กรอกแล้ว)

**เร็วและนิ่ง**
- **ไม่มี page reload ทั้งแอป** — ใช้ Server Actions / `router.refresh()` / optimistic update
- เพิ่มรายการ: optimistic UI — แถวใหม่ขึ้นทันที + ยอดใหม่คำนวณทันที แล้วค่อย sync; ถ้าพลาด → rollback แถวออก + toast "บันทึกไม่สำเร็จ ลองใหม่" + เก็บค่าที่กรอกไว้ (ห้ามล้างข้อมูลที่ผู้ใช้พิมพ์)
- optimistic ต้องไม่ทำให้ยอด "เดา" ค้าง: ระหว่างรอให้แสดงยอดที่คำนวณจากข้อมูล local พร้อมสถานะจาง ๆ ไม่ใช่ยอดนิ่งที่ดูเหมือนจริง
- haptic ตอนบันทึกสำเร็จ: `navigator.vibrate(10)` — **iOS Safari ไม่รองรับ `navigator.vibrate`** ต้องเช็คก่อนเรียกและมี fallback เป็นแอนิเมชันปุ่มยุบ 100ms (ห้ามใช้ `vibrate` เป็นตัวยืนยันผลลัพธ์เดียว)
- กดซ้ำเร็ว ๆ ต้องไม่สร้างรายการซ้ำ: ปุ่มบันทึก disable ทันทีที่กด + idempotency key จาก client (ส่ง `client_id` uuid ต่อการบันทึก 1 ครั้ง, unique ที่ชั้นแอป/DB) — กันเน็ตมือถือที่ยิงซ้ำเอง
- สถานะกำลังโหลดใช้ **skeleton ที่มีโครงเหมือนเนื้อหาจริง** ไม่ใช่ spinner กลางจอ (ไม่ให้ layout กระโดด)
- ทุกการแตะต้องเห็นผลภายใน ~100ms (ปุ่มยุบ/สี) ก่อนข้อมูลจริงจะมา

**แป้นพิมพ์/ฟอร์ม**
- ช่องบันทึกที่อยู่ใกล้ขอบล่างต้องเลื่อนขึ้นเมื่อคีย์บอร์ดเปิด (ใช้ `env(keyboard-inset-height)` เมื่อมี / วัด `visualViewport` เป็น fallback)
- ปุ่มบันทึกต้องไม่ถูกคีย์บอร์ดบัง — sheet ยืดหยุ่นตามความสูงที่เหลือ
- วันที่ใช้ `<input type="date">` แบบซ่อนช่องกรอกแต่เก็บค่าจริง + ปุ่มลัด "วันนี้ / เมื่อวาน" (ไม่ทำ date picker เองใน v1)

## 3. โครง navigation

bottom tab bar 4 แท็บ (สูง 56 + safe area) เรียงซ้าย→ขวา:

1. **หน้าแรก** (ยอดเดือนนี้ + รายการล่าสุด)
2. **รายการ** (ทั้งหมด + ค้นหา + ตัวกรอง)
3. **สรุป** (กราฟหมวด + แนวโน้ม 6 เดือน)
4. **ตั้งค่า** (หมวดหมู่, กระเป๋าเงิน, งบประมาณ, ธีม, บัญชี/ออกจากระบบ)

+ ปุ่มลอย (FAB) **+** มุมขวาล่าง เหนือแถบแท็บ → เปิด bottom sheet เพิ่มรายการ

ไอคอนประจำแท็บ (1 ไอคอน ต่อ 1 แท็บ · ห้ามใช้ไอคอนซ้ำกันหรือยืมความหมายกัน):
`หน้าแรก` บ้าน · `รายการ` ลิสต์ · `สรุป` แผนภูมิแท่ง · `ตั้งค่า` **เฟือง**
(ห้ามใช้รูปพระอาทิตย์/ดวงจันทร์เป็นไอคอน "ตั้งค่า" — นั่นคือ "ธีม" ซึ่งเป็นการตั้งค่า 1 รายการในหน้า ไม่ใช่ทั้งหน้า)

เป้าหมาย "เพิ่มรายการเร็วสุด 2 แตะ" นิยามตรง ๆ:
- แตะที่ 1 = ปุ่ม FAB → sheet เปิดพร้อมคีย์แพด และหมวดที่เดาจากรายการเดิม/เวลา/ยอดใกล้เคียง
- พิมพ์ตัวเลข (จำนวนครั้งเท่าที่จำเป็น — ไม่นับเป็น "แตะ") → แตะที่ 2 = บันทึก
- รวมจากหน้าแรกจริง = 3 การแตะ (FAB, พิมพ์, บันทึก) — ถ้าต้อง 2 แตะจริงต้องมีปุ่มลัด "จ่ายซ้ำรายการเดิม" ซึ่งจะใส่ใน v1.1 หลังมีข้อมูลใช้จริง
- รายการใหม่ค่าเริ่มต้น = **จ่าย** (สัดส่วนการใช้งานจริงสูงกว่า) · สลับ รับ/โอน ด้วยชิปที่หัว sheet

- ตัวเลขเงินที่แสดงต้องมาจากยอดเดียวกันทั้งแอป (หน้าแรก/รายการ/สรุป ของเดือนเดียวกันต้องเท่ากัน) — ถ้าไม่เท่ากันถือเป็นบั๊ก ไม่ใช่เรื่องแสดงผล
- ลิสต์ยาวใช้ keyset pagination (`occurred_at` + `id`) ไม่ใช้ OFFSET
- ทุก error ต้องมี "ลองใหม่" และห้ามลบข้อมูลที่ผู้ใช้กรอกไว้
- ข้อความ error ไม่มีศัพท์เทคนิค (ห้ามโชว์ error code ของ DB/HTTP ให้ผู้ใช้เห็น) — เก็บรหัสไว้ log ฝั่ง server

## 5. Accessibility (ห้ามตัดออก)

- ขนาดแตะ 44px, คอนทราสต์ตามตาราง 1.1 (วัดแล้ว), ห้ามใช้สีเป็นตัวเดียวบอกความหมาย (มี `+`/`−`/คำกำกับเสมอ)
- โฟกัส: ทุก element ที่โฟกัสได้มี `focus-visible:outline-2 outline-focus outline-offset-2` — ต้องเห็นบนพื้นทั้งสองโหมด
- bottom sheet ใช้ `<dialog>` ได้ focus trap และ `aria-modal` ฟรี · ปิดแล้วคืนโฟกัสไปที่ FAB
- หลังบันทึกสำเร็จ: ประกาศด้วย `aria-live="polite"` ("บันทึก ฿120 หมวดอาหาร แล้ว") ไม่ใช่แค่ toast ที่มองไม่เห็น
- ไอคอนเดี่ยว ๆ ต้องมี `aria-label` ภาษาไทย · ตัวเลขเงินให้ใส่ `aria-label` แบบอ่านเต็ม ("หนึ่งร้อยยี่สิบบาท") เมื่ออยู่ในบริบทที่ต้องอ่านออกเสียง
- เคารพ `prefers-reduced-motion` และ `prefers-color-scheme`
- ฟอร์มใช้ `label` จริง (ไม่ใช่ placeholder ทำหน้าที่แทน label)

## 6. PWA

- `manifest.webmanifest`: `name` "จดจ่าย", `short_name` "จดจ่าย", `display: standalone`, `start_url: /`, `theme_color` แยกตามธีม (`#EAEFF4` / `#0B1220`), `background_color`, ไอคอน 192/512 + maskable 512
- `<meta name="theme-color">` 2 ค่าเมื่อ media — ให้แถบสถานะกลืนกับแอป (แอปการเงินที่แถบขาวโพลนดูไม่เนทีฟ)
- service worker: cache app shell + หน้าการตั้งค่าเป็นหลัก (ไม่ cache ข้อมูลการเงินแบบยาว) · ข้อมูลใช้ stale-while-revalidate สั้น ๆ
- ออฟไลน์ใน v1 = **อ่านอย่างเดียว**: แสดงยอด/รายการที่แคชไว้ + แถบ "ออฟไลน์อยู่" · ปุ่มบันทึก disable พร้อมข้อความ (คิวออฟไลน์ยังไม่ทำ — ดูข้อ 7)
- เหตุผลเสริม: แคชชุดนี้ยังกลบ cold start ของ Neon Free ได้ด้วย — compute หลับหลังไม่มี query 5 นาที และปลุกใช้เวลา ~1.8 วิ (median) ซึ่งปิดไม่ได้บน Free → เปิดแอปแล้วเห็นยอดจากแคชทันที แล้วตัวเลขจริงตามมาทีหลัง (แสดงจาง ๆ ระหว่างรอ ตามกติกา optimistic ในข้อ 2)
  โบนัส: ถ้าอนาคตช้าจริงตอนโหลดหน้าแรก แก้ที่ `suspend_timeout_seconds` (ปรับได้บน paid) หรือยิง query อุ่นเครื่องตอนเปิดแอป — ยังไม่ทำใน v1
- Android: ใช้ `beforeinstallprompt` เก็บ event ไว้แล้วแสดงปุ่ม "ติดตั้งแอป" ในหน้าตั้งค่า (ไม่เด้งเองทันทีที่เข้า)
- iOS: ไม่มี prompt — หน้าตั้งค่าแสดงวิธีสั้น ๆ "แชร์ → เพิ่มไปยังหน้าจอโฮม"

## 8. จุดที่ต้องเช็คบนเครื่องจริงตอนทำเฟส 2 (ค้างอยู่ ไม่ใช่คำตอบ)

1. `tnum` (ตัวเลขความกว้างเท่ากัน) ของ subset ไทย IBM Plex Sans Thai — ถ้าไม่รองรับ ต้องใช้ `ui-monospace` เฉพาะตัวเลข (ข้อ 1.2)
2. `navigator.vibrate` ใช้ไม่ได้บน iOS — ยืนยัน fallback แอนิเมชันทำงาน
3. syntax ของ `@custom-variant dark` ในเวอร์ชัน Tailwind v4 ที่ติดตั้งจริง (ข้อ 1.7)
4. ปุ่ม FAB กับ safe area บน iPhone ที่มี home indicator — ต้องไม่ทับแถบแท็บหรือโดน gesture bar
